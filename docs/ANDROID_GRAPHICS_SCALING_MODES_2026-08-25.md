# Масштабирование изображения Android

> Перед любым performance/FPS-сравнением обязателен чистый preflight из
> [`PERFORMANCE_TEST_PREFLIGHT.md`](PERFORMANCE_TEST_PREFLIGHT.md): закрыть игру после фазы,
> запустить `scripts/preflight-vivo-performance-test.ps1`, убрать диагностические процессы и
> считать замер invalid при занятом CPU или проваленном gate.

Настройка находится в `Настройки → Графика → Масштабирование изображения` и меняет геометрию
готового `SurfaceView`. Она не выбирает другое разрешение, не меняет FEX/JIT и не трогает
нативный рендер-пайплайн; вычислений на каждый кадр настройка не добавляет.

## Режимы

| Режим | Поведение |
|---|---|
| Текущее поведение (по умолчанию) | Полностью сохраняет поведение сборок до появления настройки: фиксированное разрешение вписывается с исходными пропорциями, Native занимает контейнер целиком. |
| Вписать с сохранением пропорций | Показывает весь кадр, при несовпадении формата экрана добавляет поля. |
| Заполнить с сохранением пропорций | Занимает весь экран, лишнее симметрично обрезается по краям. |
| Растянуть без сохранения пропорций | Занимает весь экран без полей и обрезки; геометрия может искажаться. |
| Целочисленное масштабирование | Использует максимальный целый множитель, помещающий кадр; при уменьшении безопасно переходит во вписывание. |
| Исходный размер 1:1 | Один пиксель буфера соответствует одному пикселю экрана; кадр центрируется и при необходимости обрезается. |
| 4:3, 16:9, 16:10, 21:9, 32:9 | Вписывает выбранный формат экрана, не меняя внутреннее разрешение. |

При фиксированном выходном разрешении буфер `SurfaceHolder` сохраняет выбранный extent, а
масштабируется только его представление. В режиме Native буфер, как и раньше, следует размеру
Android layout; для полностью фиксированного extent при сравнительных тестах нужно выбирать
одно из явных разрешений. Параметр не является CPU/FEX-оптимизацией.

## Совместимость и откат

Неизвестное или повреждённое значение preference автоматически заменяется режимом `Текущее
поведение`. Настройка входит в cross-process snapshot и применяется при следующем запуске игры;
в уже созданном игровом окне безопасно выполняется только повторная разметка view.
